# @tectra-ng/core

Behaviour without looks. Every component of `@tectra-ng/ui` stands on it. Built on `@angular/cdk`.

| Entry point | What it does |
|---|---|
| `@tectra-ng/core/config` | `provideTectra({ preset, presetOverrides, storageKey, styles, mode, darkSelector, ripple, unstyled, pt, ptOptions, locale, locales, translations, palettes, units, rootFontSize })` — global config, writes theme CSS variables (`palettes: ['teal', 'rose']` adds those accent palettes as `--tx-<palette>-<step>`; `units: 'rem'` writes every px size as rem from `rootFontSize`, default 16, so components scale with `html { font-size }`); `TxThemeService` switches at runtime: `updateTheme({ style, primary, surface })` rebuilds the preset with `createTectraPreset` and applies `presetOverrides` on top, `applyPreset(preset)`, `setMode('light' | 'dark')`, `setRipple(enabled)`, the choice as signals `style()`, `primary()`, `surface()`, `mode()`, `ripple()`; with `storageKey` the choice is kept in local storage and restored before the first render (nothing is read on the server); it writes the variables of a component group when a component registers it (`injectTokens({ button: buttonTokens })`, `registerTokens`, `registeredTokens()`), so an app ships only the token groups it uses; `injectUnstyled`, `injectPassThrough` (objects or `({ instance }) => …` functions, `mergeSections` / `mergeProps`) for components |
| `@tectra-ng/core/overlay` | `TxOverlay.open(template \| component, { origin, placement, offset, viewportMargin, layer, scroll, matchWidth, closeOnEscape, closeOnOutsideClick, restoreFocus })` → `TxOverlayRef` with `placement()` after flips, `closed`, `close()`; `txPositions(placement, offset)` for `cdkConnectedOverlay`; `txOverlayInset` on sticky / fixed chrome (measured live, only while pinned) or `provideTectra({ overlay: { viewportInsets: { top, bottom } } })` keeps panels out of headers / footers and closes them once the origin scrolls under one (for custom `cdkConnectedOverlay` panels: `TxOverlayInsets` + `watchOrigin`, and `TxOverlayRoom` — bind its `positions()` and `viewportMargin()`, call `open(insets)` / `move(insets)` and `fit(origin, panel, overlay, injector)` on the first position change so the first placement with room around the chrome goes first; CDK alone compares top placements with the viewport edge); for the panel of a field, `txFieldPositions(offset)` (below or above, lined up with the start or the end of the field) and `TxPanelWidth({ maxWidth, matchOrigin, fitContent, margin })` — bind `style()` on the panel, call `open(origin)` on open and `lock(panel, overflowing?)` on the first position change: at least the field width, grows with the content up to the cap (never past the viewport minus its margins) and keeps that width while open |
| `@tectra-ng/core/a11y` | `txFocusTrap` (auto focus, restore focus), `nextListIndex` (arrows, Home / End, PageUp / PageDown, disabled items, loop), `TxTypeahead`, `TxAnnouncer`, `uniqueId` |
| `@tectra-ng/core/forms` | base for `ControlValueAccessor` + disabled / invalid / touched state, signal forms support |
| `@tectra-ng/core/i18n` | `TX_LOCALE_US` (translations, first day of the week, date format), `TxLocaleService` (`setLocale` — returns a promise, loads a built-in locale such as `'ua'` on first use; `translate`, `formatNumber`, `formatDate`, `monthNames`, `weekdayNames`), `injectTranslations()` signal, `formatBytes(bytes, { locale, decimals, base })` — a file size with the unit names of the locale. Only English is in the bundle; another built-in locale is a lazy chunk, loaded before the app starts when `provideTectra({ locale })` names it. `provideTectra({ localeStorageKey })` remembers the locale set with `setLocale` in local storage and restores it before the first render (`TxLocaleStorage`; nothing is read on the server); `provideTxLocaleSync((code, locale) => …)` calls a function — in an injection context — with the start locale and after every change, to mirror it into the app's own translation library |
| `@tectra-ng/core/i18n/ua` | `TX_LOCALE_UA` — import it and pass it to `provideTectra({ locales: [TX_LOCALE_UA] })` to switch to Ukrainian without waiting for a chunk |
| `@tectra-ng/core/styles` | `TxStyleLoader` — loads global styles of directive-based components once |
| `@tectra-ng/core/ripple` | `txRipple` — ink wave: grows from the pointer while pressed, fades on release, starts from the centre on Enter / Space, calm fade with reduced motion. On with `provideTectra({ ripple: true })`, `TxThemeService.setRipple(true)` at runtime, or `[ripple]`; `rippleCentered`, `rippleColor`, `rippleDisabled`; tokens `--tx-ripple-{color,opacity,enter-duration,exit-duration,easing}` |
| `@tectra-ng/core/fluid` | `<tx-fluid>` / `[txFluid]` — every fluid-aware component inside takes the full width |
| `@tectra-ng/core/utils` | `optionalBoolean` input transform, `txAnimationReplay` (plays an element's CSS animation again when a key changes), the page math of the paginator (`firstToPage`, `pageToFirst`, `pageCountOf`, `pageLinksOf`), the filter rules of the table (`resolveField`, `matchesRule`, `isFilled`) and `writeToClipboard` (Clipboard API with a selection fallback, behind every copy button of the kit), `TxTimeSource` (`every('second' | 'minute')` — `Date.now()` as a signal from one browser timer per step at the start of each second or minute, shared by every analog clock and `TxClock`; no timer on the server), shared with `@tectra-ng/utils` without loading the components |

Depends on: `@tectra-ng/themes`, `@angular/core`, `@angular/cdk`.
